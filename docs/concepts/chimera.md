# Chimera mesh generation

Chimera (overset) mesh generation is a strategy for discretising complex geometries in CFD by assembling multiple overlapping structured grids rather than building a single monolithic mesh.

## The Chimera concept

A Chimera mesh consists of:

- **Near-body grids** — body-fitted structured blocks around each component, generated by SHORE
- **Background grid** — a simple Cartesian or structured block that fills the far field
- **Overlap region** — cells from different grids that spatially overlap; the CFD solver interpolates between them at run time

```
         Background grid (Cartesian)
    ┌──────────────────────────────────────┐
    │                                      │
    │    ╔══════════════╗                  │
    │    ║  Near-body   ║  ← SHORE output  │
    │    ║  O-grid      ║                  │
    │    ╚══════════════╝                  │
    │                                      │
    └──────────────────────────────────────┘
              overlap zone
```

The key advantage: each grid is generated independently and optimised for its purpose (body-fitted near-body, simple far-field). Complex multi-component geometries (wing + fuselage + nacelle) become a collection of independent near-body grids rather than one intractable topology problem.

## SHORE's role

SHORE generates the **near-body O-grid** for each surface component. Its output — a structured `(ni, nj, nk)` geo block — is one input to the Xall_GPU Chimera solver's grid assembly step.

The workflow for a complete Chimera simulation with Xall_GPU:

```
1.  shore mesh wing.stl    --ni 60 --nj 100 --nk 40 → wing.geo
2.  shore mesh fuselage.stl --ni 80 --nj 120 --nk 40 → fuselage.geo
3.  [background grid generator] → background.geo
4.  Xall_GPU: assemble Chimera system, run CFD
```

## Near-body grid requirements

For a Chimera solver to accept the near-body grid:

1. **Body conforming** — the k=0 layer must lie on the body surface. SHORE's projection guarantees this within ray-casting precision.
2. **Adequate overlap** — the outer boundary (k=nk-1) must extend far enough into the background grid to establish a valid interpolation stencil. Typical Chimera solvers require 3–5 cells of overlap.
3. **Box-shaped outer boundary** (Xall_GPU specific) — Xall_GPU's Chimera assembly expects the outer boundary to be aligned with the background grid axes. SHORE currently outputs a sphere-shaped outer boundary; box morphing is the next planned feature.
4. **No inverted cells** — `shore check` must exit 0 before passing the grid to the solver.

## Multi-block extension (roadmap)

For bodies that are not star-shaped w.r.t. their centroid (e.g. an aircraft configuration with a wing-fuselage junction), a single O-grid cannot wrap the full surface. The planned multi-block extension will:

1. Decompose the surface into structured patches by tracing feature lines
2. Generate one O-grid block per patch
3. Stitch adjacent blocks at their shared faces (C0 continuity)
4. Output multiple geo files for Xall_GPU's multi-block assembly

This is a significantly harder problem — contributions and discussion are welcome.
